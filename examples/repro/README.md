# Metal resources in an XCFramework

Reproduces conflicting Metal compilation outputs when an `apple_static_xcframework`
contains both iOS device and simulator slices.

This branch is based on the unpatched rules_apple 5.3.1 release.

Dependency graph:

```text
apple_static_xcframework (Foo) -> swift_library (FooLib) -> apple_resource_bundle (FooBundle)
```

`FooBundle` contains the Metal shader `Foo.metal`. The Swift library uses
`module_name = "Foo"` to match `bundle_name = "Foo"` on the XCFramework targets.

From the repository root, run each command separately:

```sh
export USE_BAZEL_VERSION=9.3.1

# A: Each platform works in isolation.
bazelisk build //examples/repro:FooDevice
bazelisk build //examples/repro:FooSimulator

# B: Combining the platforms fails during analysis.
bazelisk build //examples/repro:Foo
```

The combined target fails with:

```text
ERROR: file 'examples/repro/Foo.air' is generated by these conflicting actions:
Label: //examples/repro:Foo
Mnemonic: MetalCompile
```

The conflicting `MetalCompile` actions are for
`examples/repro/Foo.air`: device and simulator compilations use different Metal
target triples but declare the same output path. The `.metallib` output also
ignores the XCFramework slice discriminator.

Expected: both slices build successfully, with a separate compiled Metal library
inside `FooBundle.bundle` in each framework slice.

Test environment: Bazel 9.3.1, Xcode 27.1 (27A9275), macOS 27.0.1.
